\section{工程落地与展望}
\label{sec:deployment_outlook}

FinTrace的工程实现以可运行、可复现和可扩展为核心原则。项目采用模块化 Python 架构，将用户入口、Agent Harness、金融工具、数据处理、Prompt管理、评测与部署各层解耦，使单个模块能够独立测试与替换，降低系统演化成本。

\subsection{工程实现与部署}

系统同时支持本地CLI与FastAPI两种部署形态。CLI可直接调用核心run\_agent()接口，适用于开发调试与现场演示；FastAPI将同一Agent封装为标准化HTTP服务，便于 Web 前端或外部系统集成调用。模型接口采用OpenAI-compatible协议封装，Prompt则按请求解析、动作规划、证据审查、动作修复与最终生成等职责进行版本化管理。

\subsection{应用与落地可行性}

FinTrace不依赖专用金融大模型的重新训练，而是利用通用模型完成语义理解、调查决策与解释生成，将财务计算、关系搜索与时间过滤交由确定性工具执行，从而以较低训练成本实现持续迭代。数据、工具与模型均通过统一Schema解耦，后续可逐步替换数据源Embedding模型、语言模型或检索索引，具备良好的可演进性。

面向个人投资者，系统可用于公司事实查证、风险线索整理与研究辅助；面向专业场景，可进一步接入授权金融数据库、内部研究资料与更完整的知识图谱。应用层可以扩展，但核心边界保持不变：模型负责组织研究过程，关键金融事实必须由工具产出并由Evidence支持。

\subsection{局限性与未来工作}

当前系统仍受数据覆盖范围与研究边界制约。公开主要股东数据尚不足以独立还原全部实际控制关系；实时行情、宏观指标与完整新闻舆情仍需外部接口补充；长期记忆机制与复杂调查策略有待在更大规模真实会话中持续验证；财务风险规则仅能提供进一步核查线索，不能替代审计结论或投资决策。后续工作将聚焦以下方向：扩展实时金融与新闻舆情接入、补充非上市主体及控制关系数据、完善长期研究记忆机制，并加强Claim级别的自动核验与来源冲突检测。

\subsection{结论}

本文提出FinTrace，一套面向上市公司研究的证据驱动型可追溯金融智能体。系统通过可回答性 Gate、确定性快速路径与有界调查机制，将多源金融数据、专业工具与 Evidence Ledger 组织为可执行、可验证且可审计的研究过程。FinTrace 的目标并非让大模型记忆更多金融事实，而是使其在明确的能力边界内选择正确的调查动作，并让最终结论始终受数据、时间与证据约束。随着评测体系、实时数据接入与关系图谱的进一步完善，该架构可真正扩展为面向个人投资者与研究人员的可信金融研究辅助系统。
